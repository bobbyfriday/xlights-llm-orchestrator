## Why

The batch pipeline hides every creative decision inside agent prompts and cached JSON. Steering it means a yes/no checkpoint, a `--note` on `xlo regen`, or hand-editing a brief in a browser form; the only way to see what the Director or Generator "thought" is to read a cache file after the fact. It also needs its own LLM API key, runs ~30 LLM calls per show (the per-section Generator alone is ~21 of them and ~60% of run cost), and has grown an automation harness around those calls (panel, Judge, visual critic, refine loop, revision log, telemetry, A/B) whose automatic review loop never produced shows the user trusted more than their own eyes.

Meanwhile the user already works in Claude Code. The judgment the agents perform (read the music, design the show, decide what to fix) is exactly what a conversation is for; the realization (beat grids, weave, triggers, settings strings, QA, `.xsq` patching) is exactly what code is for. This change splits the project along that seam: Claude Code drives the judgment through project-local skills and commands, and the Python package becomes a deterministic, LLM-free toolkit of file-in/file-out stage commands.

## What Changes

- **Claude Code owns judgment.** Project-local skills carry the sequencing guide, effects catalog, layering guide, scene and trigger cookbooks, layout semantics, and a "how to write a creative brief" authoring guide. Project-local commands (`/xlo:analyze`, `/xlo:design`, `/xlo:realize`, `/xlo:apply`, `/xlo:review`, `/xlo:finalize`, `/xlo:video`, `/xlo:init-layout`) drive the stages, calling the CLI through Bash and doing the creative work in the conversation.
- **One judgment artifact: the creative brief.** Claude writes `creative_brief.json` (the existing schema-backed `ShowPlan`) directly. The brief gains an optional per-section `fabric` block (carrier effect, alternation, cell length in beats, blend) so the few knobs the per-section Generator used to set are directable from the brief; when absent, code chooses.
- **`xlo` becomes a deterministic stage CLI** operating on the song's cache dir: `analyze` (audio + lyrics + a bounded human-readable **analysis digest**), `groups` (targetable groups + placeable types + scene ids, i.e. the brief vocabulary), `validate-brief` (structured errors Claude can act on), `realize` (brief → `instructions.json`, no LLM), `apply` (emit to live xLights), `qa` (deterministic findings → `qa.json`), `stills` (preview PNGs per section), `finalize` (save + offline `.xsq` patches), `video-plan` (time and media-plan a story Claude wrote), `init-layout` (deterministic classification + a review file for Claude to resolve). Interpretation (what the song is, where its boundaries fall) is a conversation over the digest, not a file.
- **Review is manual.** The human watches the show, says what to change ("redo 1:05 to 1:30, calmer, bluer"), Claude edits the brief, re-realizes, re-applies (full re-emit, as regen does today). No automatic critic or Judge loop.
- **BREAKING** — the per-section Generator agent is removed; `realize` derives the fabric deterministically (today's fallback weave and curated composites become the main path, steered by the brief's fabric fields).
- **BREAKING** — `xlo run`, `xlo regen`, `xlo edit-brief`, `xlo report`, `xlo ab` and the `--refine/--auto/--no-browser/--max-iterations/--no-log` flags are removed.
- **BREAKING** — the `pydantic-ai` dependency, the per-role model registry and `config.yaml`, provider routing, and the model-fingerprint cache namespacing are removed. LLM artifacts move up to the song dir (`<song>/creative_brief.json`); pre-change namespaced caches go cold. `ANTHROPIC_API_KEY`/`GEMINI_API_KEY` are no longer required (only `GENIUS_ACCESS_TOKEN` for lyrics).
- **Removed** — the analyst panel and synthesizer, the Director/section-redesigner agents, the Judge, the visual critic, the refine loop (RevisionBrief, escalation ledger, BestTracker, plateau), the live SSE progress server, the browser brief editor, telemetry and `usage.json`, the revision log, the A/B harness, the Videographer and layout-classifier agents, the guide-extract slicer, and their tests.
- **Kept unchanged** — `xlights-core` (analysis, stems, lyrics, preset library, layout semantics, REST client), `xlights-mcp`, and every deterministic realization layer (beats, weave, triggers, timing, phrasing, faces, matrix text, color script, transitions, QA rules, fseq metrics, finalize). Cheap checks the Judge and critic used to make (dark mid-energy, repetition, placement rules) stay as deterministic QA findings in `qa.json`.
- **Video and layout onboarding move to skills.** Claude writes the video story (logline, motifs, one beat per section) under a skill; `xlo video-plan` validates, times, and media-plans it. `xlo init-layout` writes the unresolved tail to a review file; `/xlo:init-layout` has Claude classify it into the existing overrides file and re-run.

## Capabilities

### New Capabilities
- `claude-orchestration`: the project-local skills and commands through which Claude Code drives a show: what each command does, which files it reads and writes, how the guides reach Claude, and the manual review cycle.
- `stage-commands`: the deterministic, LLM-free `xlo` CLI — one command per stage, file-in/file-out under the song's cache dir, with the analysis digest, brief validation, and brief-directed fabric as the contracts Claude writes against.

### Modified Capabilities
- `show-orchestration`: the show plan is authored by Claude in conversation (not a Director agent); effect instructions are derived deterministically from the brief (no Generator); the pipeline is a set of resumable stage commands over the cache dir; human review is the conversation; placement-rule violations are reported, not loop-gating; agent routing, render-style re-choice, design escalation, refine persistence, the per-section generator prompt, the plateau stop, and the browser brief editor are removed.
- `music-interpretation`: the analyst panel, synthesizer, MusicBrief, panel configuration, and the description review gate are removed; the human-readable song description becomes a deterministic analysis digest Claude reads and discusses.
- `show-refinement`: the Judge, scoped regeneration, bounded loop, checkpoints, anti-oscillation, and visual-critique coupling are removed; deterministic evaluation remains as the `qa` stage command.
- `visual-critique`: the multimodal critic and its loop coupling are removed; offline still rendering remains and serves the `stills` stage command.
- `revision-log`: removed entirely.
- `video-script`: the storyboard's story is written by Claude under a skill; code validates, times, and media-plans it; token accounting and model pricing requirements are removed.

## Impact

- **Packages**: `xlights-orchestrator` loses `agents/` (except the catalog helpers, which move to `pipeline/`), `models/`, `live_server.py`, `brief_editor.py`, `telemetry.py`, `reporting.py`, `revision_log.py`, `refine.py`, `music_brief.py`, `pipeline/{run,regen,refine_loop,ab,visual}.py`, and the `pydantic-ai` dependency. It gains `pipeline/digest.py`, `pipeline/validate_brief.py`, `pipeline/stills.py`, and a rewritten `cli.py`. `xlights-core` and `xlights-mcp` are untouched.
- **Repo**: `.claude/skills/xlo-*` and `.claude/commands/xlo/*.md` are added; the five guide files stay at the repo root as the single source and the skills point at them.
- **Tests**: ~24 test modules that exercise the agents, refine loop, live server, brief editor, telemetry, reporting, or A/B harness are deleted or rewritten; the golden pipeline test is re-based on a fixture brief instead of a stubbed Generator. Hermetic tests on realization, QA, timing, and the new validate/digest commands remain the suite's core.
- **Docs**: README, `docs/usage.md`, and the architecture pages are rewritten around the command flow; `.env.example` drops the LLM keys.
- **Users**: the way a show is made changes completely (a Claude Code session instead of `xlo run`). Existing caches for analysis and targetable groups are reused; cached briefs and instructions under the old `m-xxxxxxxx/` namespace are ignored.
