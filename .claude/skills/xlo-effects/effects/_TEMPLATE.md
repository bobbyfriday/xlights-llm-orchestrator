# <Effect>

One file per xLights effect. Two blocks: **Corpus facts** (generated by the miner; do not hand-edit)
and **Craft** (hand-written; survives re-mining). Keep every number in facts; keep every opinion in
craft. Cite an exemplar for any opinion the corpus does not support.

---

## Corpus facts

> Written by `xlo mine-effect "<Type>" --write` (`xlights_core/knowledge/effect_miner.py`); never
> hand-edit. The header states the corpus size, the share of sequences and songs that use the
> effect, and the sources by placement count, labelled "Song (sequencer)".

### Where it is placed
Prop classes by share. Which classes it is native to, which it is rare on.

### Dials observed
One row per setting key: the observed values with shares, the observed numeric range, and the
share that is value-curved instead of static. Include buffer style / transform, layer method,
fade in/out and transitions — they are dials too.

### Value curves
Which parameters are curved, the shapes (Ramp, Saw Tooth, Sine, Ramp Up/Down, Timing Track Fade…)
with the exact strings that occur most, so a layer can copy them.

### Palette habits
How many colors; black as a color; sparkles; the top palettes.

### Duration
In seconds and in beats where the source has a beat track; the cell / phrase / hold split.

### Stacking
Share with ≥1 concurrent partner on the same model; what sits above it (with the upper layer's
blend); what sits beneath; the full stack compositions that recur; for same-type twins, how the
two layers differ.

## Craft

### Identity and role
What it renders in one paragraph; what each dial physically does; which stack roles it plays
(bed / carrier / feature / overlay / mask / accent) and which it never plays.

### Thematic fit
What the effect *says* (rising, spinning, winding, falling, breathing…) and which songs, holidays
and lyrics that serves. Palette interactions that change the reading.

### Anchors (starting points, not a menu)
Five to eight named settings the pros reach for, each with its knob values, the catalog look that
carries that key signature, where it is used, and the one or two dials you are expected to move
off it. Then the **dials** table: every knob, its sane range, what moving it does, and the corpus
values to pick from. Then **how to permute**: the moves that make the next section different
without becoming random.

### Layering recipes
Named stacks top→bottom with blend per layer, what each layer contributes, and when to use it.

### Value curves
Shape → musical use → exact string. Which dial to curve for a build, a breath, a beat pump, a
settle. What needs a timing track.

### Prop fit and render style
Which prop classes, with buffer style and transform per class; group canvas vs per-model; what
transforms do on a tree vs a matrix vs a line.

### Timing
Cell / phrase / hold lengths in beats; fades and transitions that go with each; what abuts and what
overlaps.

### Exemplars
File, time range (m:ss), section, prop, the stack top→bottom with settings and colors, and one line
on why it works. Light of Christmas first when it has one.

### Anti-patterns
What reads badly, and why, including the ones our own pipeline has produced.

### What code can realize today
Which anchors map to a `look_id` + `knobs` on a `stack` layer; which settings go in the layer's
`settings` (value curves, blur, sparkles, transitions) versus its fields (blend, transform,
fades, render style); validation limits (knob ranges); anything code still cannot place.
